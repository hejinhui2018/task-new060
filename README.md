# 快速换装预演台（Quick Change Booth）

剧院服装组的换装排练工具：把纸表上的“这一场穿什么、下一场换什么”变成可预演的方案。
在合成彩排之前，提前发现扣子顺序矛盾、层级遮挡、行走时间不够、服装师/换装位撞车等问题。

技术栈：React 18 + TypeScript + Vite，数据保存在浏览器 `localStorage`，无任何后端依赖。

## 快速开始

```bash
npm install
npm run dev      # 开发预览
npm run test     # 运行全部测试（vitest）
npm run build    # 类型检查 + 生产构建
```

内置示例《夜航西飞》：**两名演员、六个场次**，其中林澜在二幕→三幕之间有一次
**窗口 49 秒、穿脱 45 秒**的快速换装（余量仅 4 秒），以及一次“全部可预穿、不占换装位”的换装。

## 数据模型

| 概念 | 说明 |
| --- | --- |
| 场次 Scene | 名称、开始秒数、时长 |
| 出场 Appearance | 演员在某场的上/下场时间（相对场次）与上/下场侧台（左/右）、穿着造型 |
| 服装单品 Garment | 穿着层级（0 最贴身）、穿/脱耗时、是否可预穿、不可同穿列表 |
| 造型 Outfit | 一组单品 |
| 先后规则 Rule | “A 必须先于 B”（分别约束穿上或脱下） |
| 换装任务 Task | 由相邻两次出场造型不同自动派生；可锁定人工安排（换装位 + 服装师 + 开始时间） |
| 换装位 Station | 所在侧台、距左右侧台的步行秒数 |
| 服装师 Dresser | 人员；跨换装位有赶路时间（`transferSec`，默认 10 秒） |

## 调度规则（引擎行为）

1. **层级遮挡**：穿、脱某件单品时，身上不能有层级更高的单品。由此基础顺序恒为
   “先全部脱（高层先脱）→ 再全部穿（低层先穿）”，两造型的公共底层全程不动；
   需要在里层加衣服时，外层会被临时脱下再穿回（示例的 45 秒换装链即是如此）。
2. **可预穿**：目标造型中新增、标记可预穿、能被现行外层遮住、与现行穿着兼容、
   且预穿后仍能留在公共底层的单品，在上一场期间提前穿好，不占换装窗口。
3. **不可同时穿着**：互斥单品自动满足“先脱后穿”；造型内若直接包含互斥单品，会在校验中报警。
4. **必须先后关系**：叠加在层级物理之上；同层单品可被规则重排，与层级矛盾的规则判为无解并诊断。
5. **行走窗口**：换装窗口 = 下场时刻 + 步行至换装位 → 上场时刻 − 走回侧台。
6. **资源互斥**：同一换装位、同一服装师的占用区间不得重叠；服装师跨换装位需扣除赶路时间。
7. **步骤不被打乱**：窗口内步骤严格按依赖顺序连续执行，系统不会为了填满时间而重排步骤。
8. **锁定重排**：锁定的任务原样放置并校验；系统只对其余任务做贪心重排
   （按下场时间顺序，在“换装位 × 服装师”组合中取最早完成、奔波最少者）。
9. **无解诊断**：保留最后有效方案继续展示，并指出首个卡住的上场点（演员/场次/时刻）、
   缺少的秒数，以及原因——服装依赖冲突、时间窗不足，或具体被哪个任务占用的服装师/换装位。

## 界面

- **场次轨道**：六场戏的时间块；**演员泳道**：造型色块 + 换装块（行走/等候/穿脱/余量/预穿分段着色）。
- **资源泳道**：换装位与服装师的占用情况，一眼看出谁被谁占用。
- **播放头**：红色游标，可在时间尺上拖拽；`←/→` 微调，`Shift+←/→` 或顶栏按钮做**单步预演**（逐节点跳转），右栏步骤清单同步高亮当前步骤。
- **步骤清单**：选中换装块后显示每一针的穿/脱、层级、耗时与预穿标记。
- **方案对比**：`设为对照 A` 快照当前方案，之后每次重排都与 A 并排比较最小余量、人员奔波、换装位利用率。
- **撤销/重做**：`Ctrl+Z` / `Ctrl+Shift+Z`（或 `Ctrl+Y`），全部数据修改均可撤销。
- **刷新恢复**：每次修改自动写入 `localStorage`，刷新后完整还原；存档损坏时回退到内置示例。
- **数据编辑**：顶栏 `✎ 数据编辑` 维护场次、出场、单品、造型、规则、人员与换装位、任务锁定。

## 测试（29 个用例）

- `tests/layers.test.ts` — 层级步骤生成：45 秒换装链、公共底层、预穿的接受/拒绝、互斥顺序、规则重排与冲突。
- `tests/schedule.test.ts` — 行走窗口压缩诊断、资源互斥（单服装师撞车）、换位赶路时间、锁定重排、锁定冲突诊断、依赖无解诊断。
- `tests/metrics.test.ts` — 最小余量、换装位利用率、人员奔波指标及两套方案的可比性。
- `tests/persistence.test.ts` — 刷新恢复、撤销重做、无解时保留最后有效方案、损坏存档回退、锁定预填。
- `tests/app.test.tsx` — 应用首屏渲染冒烟。

```

  store/     store.ts（撤销重做、持久化、对照方案） react.ts（绑定）
  components/ Timeline / Inspector / Editors / TaskAssignment
tests/       上述五个测试文件
```
