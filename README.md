# 快速换装预演台

剧院服装组的快速换装（quick change）排演工具。把纸表上的「这一场穿什么、下一场换什么」搬进时间轴：维护场次时间、演员造型、服装单品与穿着规则，在场次之间建立换装任务并分配换装位与服装师，系统自动生成合法的穿脱步骤、算上往返侧台的行走时间，判断每一次换装能否赶在下一次上场前完成——在合成彩排之前，把扣子顺序和人员冲突都暴露出来。

技术栈：React 18 + TypeScript + Vite + Vitest，数据保存在浏览器 localStorage，刷新不丢。

## 快速开始

```bash
npm install
npm run dev        # 开发服务器
npm run test       # 运行全部测试（38 个）
npm run build      # 类型检查 + 生产构建
npm run preview    # 预览构建产物
```

打开后即是内置演示：**两名演员（阿黎、小满）、六个场次（序幕→谢幕）、一次 45 秒快速换装**（第4场《宫宴》下场到第5场《诀别》上场只有 45 秒，默认方案余量仅 3 秒）。试试这些操作：

- 在时间轴上点任意换装任务块 → 右侧显示完整穿脱步骤清单；
- 把《宫宴》→《诀别》任务的换装位改成「后区换装间」→ 立刻无解，诊断指出缺几秒、为什么；
- 把两个任务的服装师改成同一个人 → 资源互斥导致后者被推迟；
- 点「🔒 锁定当前安排」锁住一个任务，再改别的任务 → 系统只重排未锁定的任务；
- 顶栏「存为方案A」→ 调整 →「存为方案B」→「对比方案」；
- 方案无解时，顶栏可一键「恢复最后有效方案」；
- 「下步 ▸」单步预演，或点「▶ 播放」让播放头走过全剧。

## 界面导览

- **场次轨道**：六场戏的时间块，起止时刻一眼可查。
- **演员行**：每场造型的穿着清单、上下场口（左/右）、晚上场/早下场秒数；场次之间的换装任务块分段显示 走入（斜纹）→ 等待（棕色，仅被资源卡住时）→ 穿脱（绿=有余量，红=迟到）→ 走出 → 余量（细绿条）/ 超时（红色溢出），竖线为上场死线。
- **资源泳道**：每位服装师、每个换装位一行，占用块按演员着色，重叠冲突会红框标出。
- **播放头**：琥珀色竖线；演员行标签实时显示其状态（场上/走向换装位/穿某件/等待……）。
- **步骤清单**（右侧）：预穿步骤（不占窗口）与窗口内步骤，含每步的开始/结束时刻，播放时高亮当前步。
- **方案指标**（右侧）：最小余量、迟到数、人员奔波（秒/趟）、各换装位利用率。

## 领域模型与规则

### 穿脱步骤生成（`src/domain/sequence.ts`）

从前一造型到目标造型，按以下规则生成合法序列，**只做必要的穿脱，绝不为填满时间打乱依赖**：

1. **层级遮挡**：穿/脱 layer=L 的单品时，身上不能有任何 layer>L 的单品。必须操作里层时，先把外层**临时脱下再穿回**（步骤标记「临时」）。
2. **可预穿**：`preWearable` 且能藏在前一造型里面（层级低于其最外层、且不与其互斥）的单品，在上一场演出期间提前穿好，不占换装窗口。
3. **互斥**：`incompatibleWith` 中的单品绝不同时上身，先脱后穿。
4. **必须先后**：规则「A 先于 B」要求 B 穿上时 A 已在身上（A 不在目标造型时规则自动失效；规则成环会报错）。

算法按层推进：每轮找到最深层的需求，脱开它上方所有遮挡，再完成该层的脱与穿。

### 调度（`src/domain/schedule.ts`）

- 任务窗口 = 上一场实际下场时刻（可设早下场）→ 下一场实际上场时刻（可设晚上场）。
- 窗口内：走入（退场口→换装位）+ 穿脱 + 走出（换装位→上场口）。跨侧台加 10 秒后台穿行。
- **资源互斥**：换装位、服装师、演员本人同一时刻只能服务一个任务；服装师在换装位间移动要加奔波时间（同侧距离差，跨侧 +10 秒）。
- **锁定重排**：锁定的任务保持人工安排（换装位/服装师/开始时刻）不动，系统按就绪时刻顺序把未锁定任务插到最早可行位置；未指定资源的任务自动选择「最早完成、奔波最少」的组合。锁定任务互相冲突会被明确报告。
- **无解诊断**：找出期限最早却赶不上的任务，报告首个卡住的上场点、缺少的秒数，以及原因——是某服装师/换装位被哪个任务占用到几点，还是换装本身耗时超出窗口（含层级遮挡/互斥/先后规则的具体说明）。无解时界面保留并可一键恢复**最后有效方案**。

### 方案对比

任意时刻可把当前方案存为方案 A/B 快照，对照**最小余量、迟到任务数、人员奔波、换装位利用率**（含每个换装位分项），更优项标绿。

## 状态与历史

- 所有编辑进入撤销栈（上限 100 步），`撤销/重做` 随时可用；
- 每次变更自动写入 `localStorage`，刷新页面后恢复；
- 最近一次可行方案单独保存，供无解时回退。

## 目录结构

```
src/
  domain/          纯领域逻辑（无 React 依赖，可单测）
    types.ts       实体与常量（场次/造型/单品/规则/任务/资源）
    sequence.ts    穿脱步骤生成
    schedule.ts    调度、资源互斥、指标、无解诊断
    seed.ts        内置演示数据
  state/
    store.ts       reducer + 撤销重做 + 持久化（纯函数）
    AppContext.tsx React 上下文（派生调度、播放头、最后有效方案）
  components/      界面（时间轴、编辑面板、详情、诊断、对比）
```
